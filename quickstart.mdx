Use this guide when you want the shortest path from first access to useful product and API documentation.

## Prerequisites

Before you begin, make sure you have:

- access to the correct Centra workspace
- the product area you want to work on first
- access to API reference endpoints where needed

## What you will get from this guide

By the end of this quickstart, you should know:

- where to start in the docs
- when to use a workflow page vs an API reference
- which product area to open next

## Recommended path

<Steps>
  <Step title="Start with Auth">
    Open **Auth** first if you need user login, app login, session handling, or credentials before doing anything else.
  </Step>

  <Step title="Move to CRS for core setup">
    Open **CRS** when you are preparing inventory, pricing, policies, taxes, or reservations.
  </Step>

  <Step title="Use Bridge for partner-facing flows">
    Open **Bridge** when you are handling callbacks, HotelRunner-style APIs, or custom partner formats.
  </Step>

  <Step title="Use Developer for implementation details">
    Open **Developer** when you need credentials, integration setup, and API usage examples for technical teams.
  </Step>

  <Step title="Switch to API reference when you need exact contracts">
    Use the generated API docs when you need the full request and response contract beyond the examples in these guides.
  </Step>
</Steps>

## When to use the workflow guides

- when you want business context
- when you want a recommended order of operations
- when you want customer-friendly examples before reading raw API schemas

## When to use the API reference

- when you need the full contract for implementation
- when you need to inspect optional fields and exact response types
- when you are validating a request or building an integration

## API entry points

- backend API reference is available through `/docs` and `/doc`
- bridge API reference is available through `/docs` and `/doc`
